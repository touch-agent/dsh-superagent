Add the two Ticket forms, tracked and lightweight, and the inline path a lightweight Ticket runs without an Assignment or a worker Session. Each inline run gets a token: every action and the end name it, a late callback from an earlier run is refused, and the run plus the step's position make each action's stage id unique, so a repeated Action stays one row per time it ran. A lightweight Ticket records one `action` span per step under its Trigger's trace as the step runs, in order, followed by a `report` span that is dated no earlier than the last action when its run ends. It names the Inputs its run read, so a person's later message it handled is taken up in the disposition rather than handed back to Eval; an Input it did not read keeps waiting until the run ends and can then go back to Eval rather than being lost. It takes up the person's original message and ends `completed` or `dropped`. Its actions are limited to `read` and `draft`, because `commit`, `send` and `spend` need a tracked Ticket and a worker Session (R5); the kernel refuses such a step and revalidates the Mandate at the action's level. A person's later message on one of its Threads resumes it inline under the same Mandate. Tracked remains the default form, and a deployment without an inline executor refuses such an accept and rolls its Decision back.
