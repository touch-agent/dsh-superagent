# 026 UI 第三批：主 Agent 卡、四项导航、浮层通知与文件页

> 状态：已实现（2026-11-13），四项各自默认开启、逐项可回退。
> 输入：[021 界面重构提案](021-ux-redesign.zh.md) 的「主 Agent 人格入口、任务/通知/文件/设置四项导航、全局通知入口、文件页」，[022 上游扩展点请求](022-harness-extension-requests.zh.md) 的边界核对，以及 [024 第二批](024-ux-second-batch.zh.md) 已落地的三入口、任务详情 v2 与首次说明。
> 边界：只用插件已暴露的扩展点；不删除 E2/E3 记录，不改 Approval、Mandate、Dispatch、Profile 或 Store schema，不把宿主限制写成已完成。

## 1. 这一批做了什么

| # | 提案条目 | 落地 |
| --- | --- | --- |
| ① | 主 Agent 顶部固定卡 | 放在**插件任务视图顶部**（不是宿主菜单顶）：可改名、可换头像（4 个预设或本地图片）、显示主会话的一句话状态与「进入主会话」；名字和头像持久化在浏览器插件状态，不写服务端 |
| ② | 导航收敛到四项 | 插件面板内只保留「任务 / 通知 / 文件 / 设置」；概览收进任务与设置，系统页进入设置；右栏重复的「系统事件」「任务」标签在四项模式下不再注册；宿主自己的「新建会话 / 插件」行与工作区区域不在插件控制范围，保留并在 §5 标注 |
| ③ | 全局通知入口 | 插件在 `shell.overlay` 注册一个常驻浮层按钮，代替宿主级通知 nav 项：有待处理时显示计数与最近一条摘要，点开现有通知抽屉；无待处理时显示静默态；按钮可键盘聚焦，抽屉可用 Esc 或关闭按钮收起，关闭后焦点回到打开它的按钮 |
| ④ | 文件页 | 新的一级页把现有 `GET tasks` 的 `deliverables` 按任务列出；`http(s)` 产出物直接打开，其余跳到所属任务；只读，不新增文件记录，不是宿主的文件浏览器 |
| ⑤ | Feature Flags 与限制清单 | 四项各有独立开关与回退，不删除 023/024 的记录和页面；宿主仍做不到的事（L1–L7）逐项列在 §5，并对应到 docs/022 的请求编号 |

## 2. 主 Agent 卡

- 位置：`TasksPage` 顶部，位于首次说明和任务列表之前；它属于插件任务视图，不会出现在宿主侧栏、主菜单或工作区顶部。
- 内容：头像、名字（默认「小助」）、「主 Agent」标签、一句状态、「改名」「换头像」「进入主会话」。
- 状态优先级：已暂停 > 正在连接 > 待你处理（数量）> 正在处理（数量）> 待命。数据来自 `GET state`（`masterId`、`paused`、`load.running`）与 `GET tasks` 的 `attention`；没有主会话时按钮禁用，不创建主会话。
- 「进入主会话」调用已有的 `openSession(masterId)`，只打开现有主会话，不新建会话，也不授予权限。
- 改名：最多 24 个字符，去掉首尾空白；空值恢复默认名。保存在 `dsh-superagent/master-identity` 的浏览器 localStorage。
- 头像：4 个预设（极光、晚霞、森林、石板）或本地 PNG/JPEG/WebP。本地图片在浏览器内用 canvas 裁成 96×96 并重新编码为 PNG，原始文件名、EXIF、色彩配置等元数据不会进入存储；超过 4 MB 或非图片类型会被拒绝。保存的是 data URL，仍只在本浏览器。
- 关闭 `ux.masterCard.v1` 后卡片不渲染，任务视图其余部分与 024 一致；名字和头像键保留，不会删除。

## 3. 四项导航

- `visibleTabs()` 在 `ux.navFour.v1` 开启时返回「任务、通知、文件、设置」，关闭时回到 024 的三入口或更早的七入口（取决于 `ux.opsInSettings.v1`）。
- 默认路由从「概览」改为「任务」；会话里记住的旧 `overview` 路由在四项模式下第一次读取时迁移到任务，不删除历史栈里的其他路由。
- 通知页是现有通知抽屉的完整列表版：分组、未读、全部已读和原地动作与抽屉一致；页底折叠 E2/E3 活动记录，保证 023 的事件链路仍可达。
- 文件页是只读投影；没有产出物时显示一句空态，不生成示例文件。
- 概览页仍保留在路由和回退里，但四项模式下不作为一级入口；设置里的系统/运维页仍使用原有路由与深链。
- 右栏的 `system-events` 与 `task-list` 标签在四项模式下不注册；旧标签在 `ux.navFour.v1` 关闭时照旧注册。
- 宿主自己渲染的侧栏项不归插件管：插件只能收敛**自己注册**的面板内入口，不能去掉宿主的新建会话、插件、工作区或会话行。

## 4. 浮层通知入口与文件页

### 4.1 浮层通知

- 入口在 `shell.overlay`，这是宿主提供的 frame-wide additive 座位；插件没有替换或新增宿主一级导航项的能力。
- 数据仍来自 `GET overview` 的通知投影，读游标仍是浏览器 localStorage；浮层最多显示最近一条未读摘要，点击打开现有抽屉，不新开第二个通知中心。
- 无未读时按钮显示「通知」和「暂无待处理通知」，不加红点、不弹浮层。
- 键盘：按钮是原生 `button`，可 Tab 聚焦，有 `aria-haspopup="dialog"`；抽屉打开后关闭按钮自动聚焦，Esc 关闭；关闭后焦点回到打开它的按钮。
- 关闭 `ux.noticeButton.v1` 后回到 024 的页头铃铛；浮层与铃铛不会同时出现。

### 4.2 文件页

- 来源是任务视图同一份 `GET tasks` 的 `deliverables`，按时间倒序；每行显示产出物摘要、类型、版本、所属任务与时间。
- `http(s)` 地址在新标签打开；其他引用（例如 `file:`）不给浏览器直开，而是进入所属任务，避免把本地路径当链接。
- 只展示 metadata 与已有链接，不读取、不复制、不索引文件内容；E3 的原始记录仍在任务页与事件记录里。
- 关闭 `ux.filesPage.v1` 后文件页从一级导航移除，任务详情里的产出物照旧可用。

## 5. 仍是宿主限制（不写成已完成）

下表逐项说明插件做不到什么、现在用什么替代、以及 docs/022 里对应的上游请求。**这些是限制，不是已完成项。**

| # | 宿主限制 | 插件现在的替代 | 上游请求 |
| --- | --- | --- | --- |
| L1 | 主 Agent 不能真正占据宿主主菜单/侧栏首位；侧栏顺序和固定项由宿主决定 | 在插件任务视图顶部放主 Agent 卡 | [022 §2.1 侧栏顶置主 Agent 卡与区块重排](022-harness-extension-requests.zh.md#21-侧栏顶置主-agent-卡与区块重排) |
| L2 | 不能替换宿主工作区区域；插件面板不是宿主工作区 | 任务视图仍是插件面板内的一级页，宿主工作区/会话行保留 | [022 §2.3 工作区列表投影或过滤](022-harness-extension-requests.zh.md#23-工作区列表投影或过滤) |
| L3 | 设置是插件面板内的页面，不是宿主设置弹窗 | 四项导航里的「设置」页；系统/运维页仍嵌在设置里 | [022 §2.4 设置外壳自定义页与分组](022-harness-extension-requests.zh.md#24-设置外壳自定义页与分组) |
| L4 | 宿主原生「新建会话 / 插件」行和工作区行无法由插件移除或改名 | 只收敛插件注册的入口；宿主行原样保留，未隐藏真相 | [022 §2.2 隐藏或归档宿主自动生成的会话行](022-harness-extension-requests.zh.md#22-隐藏或归档宿主自动生成的会话行)、[§2.6 主菜单项顺序与命名](022-harness-extension-requests.zh.md#26-主菜单项顺序与命名) |
| L5 | 宿主没有通知一级导航项；插件只能挂 frame-wide 浮层 | `shell.overlay` 常驻按钮 + 插件通知页/抽屉 | [022 §2.5 全局通知层与一级入口](022-harness-extension-requests.zh.md#25-全局通知层与一级入口) |
| L6 | 主 Agent 身份没有服务端或跨设备同步位置 | 名字/头像只存本浏览器 localStorage；不写服务端、不跨设备 | 无对应宿主扩展点；若需要同步需产品与服务端另行定义 |
| L7 | 文件页不是宿主文件浏览器，也没有文件索引 API | 只投影任务已有 `deliverables` 的元数据与链接 | 无对应宿主扩展点；范围就是任务交付物 |

## 6. Feature Flags 与回退

| 开关 | 默认 | 关闭后的行为 |
| --- | --- | --- |
| `ux.navFour.v1` | 开 | 回到 024 的三入口（概览/任务/设置）或更早的七入口；右栏事件/任务标签恢复注册 |
| `ux.masterCard.v1` | 开 | 任务视图不渲染主 Agent 卡；名字/头像数据保留 |
| `ux.noticeButton.v1` | 开 | 移除浮层按钮，回到页头铃铛 |
| `ux.filesPage.v1` | 开 | 文件页从导航移除；任务详情里的产出物仍可用 |

四项互相独立；刷新后生效，不迁移、不删除记录，也不需要重启。浏览器偏好键：`dsh-superagent/master-identity`（名字与头像）。

### 7.2 十秒自查与限制核对

按两项独立问题逐条自查，结论写入 PR review 评论：

1. 没用过的人 10 秒内能否说出下一步：打开面板先看到主 Agent 卡与「进入主会话」；任务页的状态、待处理数量和「查看任务/查看结果」都在首屏；通知浮层显示待处理计数与最近一条摘要，点开即可处理；文件页每行给出「打开」或回到任务。
2. 限制是否被如实标注：§5 的 L1–L7 全部写明「做不到」和替代，不把插件卡写成宿主主菜单置顶，不把插件设置页写成宿主设置弹窗，不把浮层写成宿主通知 nav 项，不把文件页写成宿主文件浏览器。
